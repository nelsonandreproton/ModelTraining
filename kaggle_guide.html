Fine-tuning Qwen2.5-1.5B-Instruct com LoRA em PT-PT — dois notebooks Kaggle: geração de dataset + treino do modelo

Visão geral do processo (dois notebooks)
  1. Notebook A — Geração do Dataset: Usa Qwen2.5-7B-Instruct no T4 para gerar ~5000 pares PT-PT sobre Portugal. Demora ~8-12h. Resultado: generated_pairs.json.
  2. Notebook B — Treino do Modelo: Fine-tune do Qwen2.5-1.5B-Instruct com LoRA no T4. Demora ~1-2h. Resultado: adaptador LoRA publicado no HuggingFace Hub.
Quota: Cada notebook usa GPU separado. Ambos cabem dentro das 30h/semana gratuitas (geração ~10h + treino ~1.5h).
Parte A — Geração do Dataset (Notebook 1)
A0

Pré-requisitos para a Geração

  1. Conta Kaggle verificada por telefone — necessária para acesso à internet (download Qwen2.5-7B do HF Hub).
  2. HuggingFace token com permissão de leitura — para descarregar o modelo gerador.
    huggingface.co → Settings → Access Tokens → New Token (tipo Read é suficiente para esta fase).
  3. O dataset base já publicado no HF Hub — o script carrega nelsondiasandre/portuguese-qa-instruct-620 para evitar duplicados. Se ainda não publicaste:
    .\venv\Scripts\activate
python upload_to_hub.py --username nelsondiasandre --dataset
A1

Criar o Notebook de Geração

  1. Vai a kaggle.com/code → New Notebook.
  2. Painel lateral → Accelerator → GPU T4 x2.
  3. Painel lateral → Internet → Internet on.
  4. Menu superior → Add-ons → Secrets → adiciona HF_TOKEN (mesmo processo do passo 2 da Parte B).
Memória RAM: O modelo Qwen2.5-7B em bfloat16 ocupa ~15 GB de VRAM. Com T4 x2 tens 32 GB total — funciona. Com P100 (16 GB) pode dar OOM; usa T4 x2.

Parte B — Treino do Modelo (Notebook 2)
0

Pré-requisitos — Antes de abrir o Kaggle

  1. Conta Kaggle verificada por telefone — necessária para acesso à internet nos notebooks (sem ela, os modelos do HuggingFace não podem ser descarregados).
    Vai a kaggle.com → Account → Phone Verification e segue os passos.
  2. HuggingFace token com permissão de escrita — necessário para descarregar o modelo base e publicar o adaptador treinado.
    Vai a huggingface.co → Settings → Access Tokens → New Token.
    Escolhe tipo Write. Copia o token — vai precisar dele no passo 2.
  3. Dataset expandido publicado no HuggingFace Hub — completa a Parte A primeiro para ter o dataset com ~5000+ pares.
    Após a Parte A, o dataset deve estar em nelsondiasandre/portuguese-qa-instruct-5k.
    Se saltares a Parte A e quiseres treinar com o dataset base (620 pares), usa portuguese-qa-instruct-620 — também funciona.
Quota GPU Kaggle: 30 horas/semana de GPU gratuito. Cada sessão é limitada a ~12h seguidas. Após ~20 min de inatividade a sessão pode ser desligada — monitoriza ativamente ou guarda checkpoints.
1

Criar o Notebook Kaggle

  1. Vai a kaggle.com/code e clica em "New Notebook".
  2. No painel lateral direito, em Settings:
    • Language: Python
    • Environment: deixa o default (não precisas de imagem custom)
  3. Activa o acelerador GPU:
    Painel direito → Accelerator → seleciona GPU T4 x2 (preferido) ou P100. T4 x2 recomendado
  4. Activa o acesso à internet:
    Painel direito → Internet → Internet on (requer verificação de telefone do passo 0).
Atenção: Sem "Internet on", o notebook não consegue descarregar o modelo Qwen2.5 do HuggingFace.
2

Adicionar o HuggingFace Token como Secret

  1. No notebook, clica em Add-ons (menu superior) → Secrets.
  2. Clica "Add a new secret".
  3. Preenche:
    • Name: HF_TOKEN
    • Value: cola o teu token HuggingFace (começa por hf_)
  4. Clica Save e certifica-te que o toggle "Attach to notebook" está activo.
Os secrets são encriptados e não aparecem nos logs. Nunca coloca o token directamente no código.

Descarregar o Adaptador Treinado

Após o treino, o adaptador está disponível em dois sítios:

  1. HuggingFace Hub (automático) — o script faz push automático. Acede em:
    https://huggingface.co/nelsondiasandre/qwen25-1.5b-pt-qa-lora
  2. Descarregar directamente do Kaggle:
    No painel lateral → Output → expande /kaggle/working/
    Clica em my_lora_model/ → Download
    Os ficheiros importantes são: adapter_config.json e adapter_model.safetensors
O adaptador LoRA é muito pequeno (~35 MB) comparado com o modelo completo (~3 GB). Apenas os pesos do adaptador são guardados.

Para usar o adaptador localmente após descarregar:

from transformers import AutoModelForCausalLM, AutoTokenizer
from peft import PeftModel

base = AutoModelForCausalLM.from_pretrained("Qwen/Qwen2.5-1.5B-Instruct")
model = PeftModel.from_pretrained(base, "./my_lora_model")
tokenizer = AutoTokenizer.from_pretrained("./my_lora_model")

Se o treino for interrompido a meio:

  1. O último checkpoint está em /kaggle/working/lora_output/checkpoint-XXXX/
  2. Para retomar, adiciona resume_from_checkpoint=True ao SFTConfig e volta a correr
  3. Alternativamente, faz push do checkpoint para o HF Hub e recomeça a partir daí

Se vires OOM (Out of Memory):

  1. Reduz per_device_train_batch_size de 4 para 2
  2. Aumenta gradient_accumulation_steps de 2 para 4 (mantém o batch efectivo igual)
  3. Confirma que bf16=True está activo (já está no script)
bf16 vs fp16: Em T4, usa bf16=True. O T4 suporta bf16 nativo e é mais estável que fp16 para treino. Em P100, experimenta fp16=True se bf16 causar problemas (P100 tem suporte bf16 limitado).
